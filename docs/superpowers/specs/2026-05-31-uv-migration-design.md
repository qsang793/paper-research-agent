# Design: Migrate Python dependency management to UV

**Date:** 2026-05-31
**Status:** Approved (design) — pending spec review
**Scope:** Backend Python tooling only. The Next.js frontend (`web/`, npm) is untouched.

## 1. Goal

Replace the current pip + two-`requirements.txt` setup with a single `pyproject.toml` + `uv.lock` managed by [UV](https://docs.astral.sh/uv/). Outcomes:

- One source of truth for dependencies, with optional groups (`api`, `eval`, `dev`).
- Modern range-based version constraints (relaxed from exact `==` pins) with a reproducible `uv.lock`.
- `Makefile` and `Dockerfile` driven by UV.
- Fix the latent Docker bug where API dependencies are never installed.
- Keep an auto-exported `requirements.txt` as a fallback for environments without UV.

## 2. Current state

- `requirements.txt` (root): core ML/RAG stack, mostly exact `==` pins, **plus** `ragas`/`datasets`, `pytest`/`pytest-cov`.
- `api/requirements-api.txt`: `fastapi`, `uvicorn[standard]`, `pydantic(+[email])`, `python-multipart`, `python-dotenv`, `sse-starlette`, `bcrypt`, `PyJWT`.
- No `pyproject.toml`, no lock file. Python 3.12 (Dockerfile `python:3.12-slim`).
- `Makefile install-api` runs `pip install -r api/requirements-api.txt` then `-r requirements.txt`.
- **Bug:** `Dockerfile` builder only runs `pip install -r requirements.txt` (core). It never installs `api/requirements-api.txt`, yet `CMD` is `uvicorn api.main:app …`. The image cannot run the API as written.
- **Conflict:** `python-dotenv==1.0.1` (root) vs `==1.0.0` (api).

## 3. Decisions (locked with user)

| # | Decision | Choice |
|---|---|---|
| 1 | Pinning strategy | **Relax to ranges** — lower bound = current version; cap major on fragile ML libs (see §5) |
| 2 | Dependency grouping | **core + optional groups** (`api`, `eval`, `dev`) |
| 3 | `requirements.txt` | **Keep**, auto-exported from the lock via `uv export` |
| 4 | Build tooling | **UV-ify both `Makefile` + `Dockerfile`**, and fix the missing-api-deps bug |
| 5 | `streamlit` | **Remove** the legacy Stage-1 `app/ui.py` POC and dependency; the UI path is Next.js |
| 6 | `api/requirements-api.txt` | **Delete** (consolidated into `pyproject.toml`) |

## 4. Architecture / files

### Create
- **`pyproject.toml`** — PEP 621 metadata + dependencies + groups + `[tool.uv]`.
- **`uv.lock`** — generated by `uv lock`, committed.
- **`.python-version`** — `3.12` (pins the interpreter UV uses).

### Modify
- **`Makefile`** — UV-based targets (see §6).
- **`Dockerfile`** — multi-stage UV build, installs core + `api` (see §7).
- **`requirements.txt`** — regenerated via `uv export` (fallback only).
- **`.dockerignore`** — keep `.venv/` excluded; confirm `pyproject.toml`/`uv.lock` are in context.
- **`.gitignore`** — ensure `.venv/` ignored (already present), confirm `uv.lock`/`pyproject.toml` tracked.
- **`CLAUDE.md`** — update the **Commands** section to UV.

### Delete
- **`api/requirements-api.txt`**.

## 5. `pyproject.toml` structure

```toml
[project]
name = "ai-research-agent"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [ ... core ... ]

[project.optional-dependencies]
api  = [ ... ]
eval = [ "ragas>=0.1.0", "datasets>=2.14.0" ]

[dependency-groups]            # PEP 735; installed by default, excluded with --no-dev
dev = [ "pytest>=8.0", "pytest-cov>=5.0" ]

[tool.uv]
package = false                # repo is a flat-layout APP (agent/ api/ ingest/), not a buildable package
```

`package = false` is required: without it `uv sync` tries to build/install the repo root as a wheel and fails (no build backend, no `src/` layout).

## 6. Makefile (UV)

- `install` → `uv sync --extra api` (core + api + dev) then `install-web`.
- `install-api` → `uv sync --extra api`.
- `run-api` → `uv run uvicorn api.main:app --reload --port 8000` (drop the manual `.venv/bin/python` detection — UV owns `.venv`).
- `migrate-e5` / `test-e5` → `uv run python scripts/...`.
- New `export-reqs` → `uv export --no-hashes --no-dev --extra api -o requirements.txt` (regenerates the fallback).
- `run-web`, `dev`, Docker, tunnel targets unchanged except where they call Python.

## 7. Dockerfile (UV, multi-stage)

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim AS builder
WORKDIR /app
ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy
RUN apt-get update && apt-get install -y gcc g++ curl && rm -rf /var/lib/apt/lists/*
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev --extra api      # core + api, no dev/eval
COPY . .

FROM python:3.12-slim
WORKDIR /app
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*
COPY --from=builder /app/.venv /app/.venv
COPY . .
ENV PATH="/app/.venv/bin:$PATH" PYTHONUNBUFFERED=1 TOKENIZERS_PARALLELISM=false PORT=8000
RUN mkdir -p /app/chroma
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=30s --start-period=120s --retries=3 \
    CMD curl -f http://localhost:${PORT}/health || exit 1
CMD uvicorn api.main:app --host 0.0.0.0 --port ${PORT}
```

This installs `api` deps (fixing the bug) and ships the venv in `/app/.venv`. The exact `uv sync` flag set (e.g. `--no-install-project`) is confirmed against UV behaviour during implementation; `package = false` already prevents installing the root.

## 8. requirements.txt fallback

`requirements.txt` is regenerated from the lock with `uv export --no-hashes --no-dev --extra api` (core + api runtime). It is committed so CI / non-UV users keep working, and refreshed via `make export-reqs` whenever the lock changes.

## 9. Verification (success criteria)

1. `uv lock` resolves with no conflict.
2. `uv sync --extra api` creates `.venv` successfully.
3. Import smoke test passes: `uv run python -c "import fastapi, langgraph, chromadb, sentence_transformers, llama_index"`.
4. `uv run pytest tests/ -q` — run and report. **Caveat:** `tests/sanity_mvp.py` and several `test_stage2_*` tests require a live Ollama/network/model and cannot pass in a sandbox; results are reported honestly, distinguishing dependency failures from runtime-dependency failures.
5. `requirements.txt` export diff reviewed — no runtime package silently dropped.
6. (Optional, heavy ~GB) `make docker-build` — run only with explicit go-ahead.

## 10. Risks

- **Resolver picks a breaking newer version** within an allowed range → mitigated by major caps on ML libs + the test gate; tighten the cap if a test breaks.
- **First `uv sync` downloads torch (~GB)** via `sentence-transformers` — expected, one-time.
- **`uv sync --frozen` in Docker fails if `uv.lock` is stale** — `export-reqs`/`uv lock` is re-run after any dependency edit.

## 11. Out of scope

- Frontend (`web/`) tooling.
- Upgrading actual dependency versions beyond what the relaxed ranges resolve to.
- `chroma_v2/` data, the `chroma/` vs `chroma_v2/` path discrepancy, and other latent issues unrelated to packaging.
